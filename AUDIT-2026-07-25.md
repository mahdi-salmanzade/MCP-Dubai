# MCP-Dubai audit, 25 July 2026

Multi-agent audit across 13 dimensions (content freshness, live upstream health,
dependency drift, code correctness, security, MCP protocol practice, docs
consistency). 149 findings were raised and each was independently
adversarially verified against a primary source; 133 survived, 16 were refuted
and dropped.

## Verdict

The engineering is genuinely solid: 90% coverage, `mypy --strict` clean, ruff
clean, a clean four-layer architecture, and a graceful credential-degradation
pattern that means the server boots on a bare machine. The problem is not the
code, it is **content decay and release drift**. Six knowledge packs were over
three months stale while the README badge advertised a uniform "July 2026"
refresh; several packs stated UAE law that was superseded in 2023; and the
version on PyPI (0.2.0, 91 tools) is two releases behind what every install
instruction in the README describes (0.4.0, 120 tools). For a server whose
entire value proposition is "trustworthy Dubai facts for an AI agent", the
wrong-fact findings are the ones that matter most.

### Security

- **WAQI API token leaked into LLM context and server logs.** `_raise_for_status` interpolated the full request URL, including `?token=<key>`, into every upstream error. Query strings are now stripped before formatting. Verified with a mocked 403 that the token no longer appears. (`_shared/http_client.py:146`)
- **lxml floor below a HIGH XXE fix.** Floor was `>=5.0.0`, installed 6.0.4; CVE-2026-41066 (GHSA-vfmq-68hx-4jfw, CVSS 7.5) is fixed in 6.1.0. This package parses untrusted scraped HTML. Floor raised to `>=6.1.0,<7` and the environment upgraded to 6.1.1.
- **Entity-expansion guard on Makani SOAP.** stdlib ElementTree does not fetch external entities but does expand internal ones ("billion laughs"). A DTD-rejection guard closes that off with no new dependency. (`data/makani/client.py`)

### Install-breaking dependency drift

- **`fastmcp>=2.2.0` could not run this code.** `server.py` calls `mcp.mount(server)` without a prefix and `await mcp.list_tools()`, neither of which exists on 2.x, and `4.0.0a1/a2` are already on PyPI (latest stable 3.4.4) with `mount(prefix=)` slated for removal in v4. A fresh `pip install mcp-dubai` was a coin flip. Pinned `>=3.2.3,<4`.
- **Upper bounds added** to httpx, pydantic, tenacity and python-dateutil, so the next major does not land silently.
- **`py.typed` added.** The package is `mypy --strict` clean but shipped no PEP 561 marker, so downstream type checking of `mcp_dubai` silently did nothing. Verified present in the built wheel.

### Timezone correctness

`UAE_TIMEZONE` existed in constants but neither date-defaulting site used it. `uae_next_holiday` and the Al-Adhan prayer-times default both resolved "today" via `date.today()`, i.e. the process timezone, putting them a day behind Dubai for four hours out of every day on a UTC host. Added `uae_today()` and switched both callers.

### MCP protocol practice

- **All 120 tools now declare `readOnlyHint`, `destructiveHint=False` and `idempotentHint`,** via a single `on_list_tools` middleware rather than 120 decorator edits, so new features inherit it. `openWorldHint` correctly separates the 42 live-upstream tools from the 78 that read bundled data. Previously zero tools carried annotations, forcing cautious clients to assume the worst about every call.
- **`serverInfo.version` reported FastMCP's version (3.2.3), not the package's.** A client could not tell which release of mcp-dubai it was talking to. Now reports 0.4.0.

### The systemic fix

Six packs rotted for 3.5 months because staleness was only visible if a human
opened the JSON. Added:

- `scripts/check_knowledge_freshness.py` -- per-pack age against a
  volatility-keyed budget (high 100d, medium 190d, stable 365d), with
  `--strict` and `--json` modes. It immediately flagged `funding.json` as
  overdue, matching the audit's independent finding of expired cohort dates and
  dead URLs in that pack.
- `tests/test_biz/test_knowledge_freshness.py` -- blocking structural
  invariants (required keys, known volatility vocabulary, no future-dated
  stamps, https `verify_at`). Staleness itself is deliberately *not* a test
  failure: a PR touching unrelated code should not go red because content aged.
- `.github/workflows/knowledge-freshness.yml` -- weekly check that opens or
  updates a single tracking issue when a pack is overdue.
- `make freshness`, wired into `make check` and reported in CI.

The structural test caught a pre-existing inconsistency on its first run: two
packs used an undocumented `stable` volatility that no code validated.

## Needs your decision

1. **PyPI is two releases behind.** Published latest is **0.2.0** (91 tools);
   the repo is 0.4.0 (120 tools). Every install instruction in the README
   currently delivers a package that does not match its own documentation, and
   there is no `v0.3.0` or `v0.4.0` git tag, so "cut a release" needs a tag
   first. The `publish.yml` workflow fires on `release: [published]`. Suggested:
   tag `v0.4.0`, create the release, confirm PyPI, then publish `server.json`
   to the MCP Registry (the README claims registry publication that has not
   happened).
2. **Six packs still stamped 2026-04-13:** `dcde`, `founder_essentials`,
   `funding`, `gov_portals`, `halal`, `ip_trademark`. The audit found concrete
   rot in them (dead in5/DFDF/Wamda URLs, Area2071 no longer standalone, a
   stale Techstars exclusion, `moet.gov.ae` vs `moec.gov.ae` ministry naming)
   but re-verifying them is research, not a mechanical edit. `funding.json` is
   the urgent one: high volatility, already over budget, and full of dated
   cohort deadlines. The README now discloses the split honestly rather than
   implying a uniform July refresh.
3. **Development Status :: 3 - Alpha** on a 0.4.0 with 120 tools, 691 tests and
   90% coverage. Beta looks closer to the truth.

## Worth doing next, ranked

1. **HTTP response cache.** Nothing is cached; every call refetches, including
   a 10.3 MB GTFS archive. A small TTL cache keyed by URL would cut latency and
   upstream load immediately.
2. **Read the health registry.** `UpstreamRegistry` is write-only: nothing
   consumes `status` to fail fast, so a dead upstream burns full retry and
   backoff on every call. It already has the data for a circuit breaker.
   Related: `mark_success` does not reset `failure_count`, so `degraded` can
   fire on a single failure after any three historical ones.
3. **Live contract tests.** All 691 tests are respx-mocked, so nothing in the
   suite can detect an upstream changing shape. A nightly smoke job hitting one
   real endpoint per feature would have caught the CBUAE DOM change that needed
   a hotfix in 0.1.2.
4. **Unbounded payloads.** `quran_search` / `quran_surah` / `quran_juz` return
   up to 1.25 MB with no `limit` parameter, which can blow an LLM context
   window. The upstream supports `offset`/`limit` for surah and juz.
5. **Missing error envelopes.** `air_quality`, `dld` and `rta` tools have no
   `try/except`, so upstream failures escape the `ToolResponse` envelope raw.
   The `fcsc_ckan` and `quran_cloud` clients raise bare `RuntimeError` that
   most callers do not catch.
6. **Drop the last API key.** Open-Meteo has a keyless Air Quality API that
   would replace WAQI, making the server 100% credential-free for Tier 0 and
   adding dust (the pollutant that actually matters in Dubai).
7. **MCP Resources and Prompts.** 216 KB of curated knowledge packs are forced
   through the tool channel; several are natural Resources. `analyze_setup_decision`
   and `plan_query` are Prompts wearing tool costumes.
8. **`tools/list` costs ~20k tokens** on every session, and `recommend_tools`
   does not reduce it by one byte since all 120 tools ship in the listing
   regardless. FastMCP 3.x offers a search transform worth evaluating.
9. **Parameter descriptions.** 0 of 196 tool parameters carry a description in
   `inputSchema`; all arg semantics (units, currency, valid values) live in
   docstring prose that FastMCP does not parse into the schema.
10. **Dependabot and `pip-audit` in CI**, GitHub Actions pinned by SHA, and a
    top-level `permissions:` block on both workflows. Actions are currently 2 to
    4 majors behind and `publish.yml` downloads `mcp-publisher` unpinned in a
    job holding `id-token: write`.
11. **No CHANGELOG** across five releases; **no Dockerfile or HTTP transport**,
    so the server cannot be hosted for remote MCP clients.

## Refuted

16 findings did not survive verification, including several claimed broken
upstreams that responded normally when probed directly, and claimed wrong facts
that turned out to be correct or unverifiable against a primary source. The
README's headline "120 tools" and "112 of 120 keyless" both verified as
accurate against an empirical count.
