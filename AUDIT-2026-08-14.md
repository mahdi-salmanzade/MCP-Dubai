# MCP-Dubai Audit - 2026-08-14

## Executive result

The source tree is materially stronger after this audit. High-impact calculation, credential-handling, publication, upstream-validation, and knowledge-freshness defects found during review were fixed and regression-tested. The project remains correctly labelled alpha because several live integrations depend on third-party availability or credentials, and the current source release has not yet been published.

No commit, tag, package upload, registry publication, or other external write was performed.

## Date policy used

- `knowledge_date` records the latest material update in a domain.
- `full_review_date` records the last complete review of the domain.
- A targeted update records `previous_knowledge_date` and `last_refresh_scope` but does not advance `full_review_date`.
- Unchanged packs, records, and dated snapshots keep their earlier dates.
- This report and every materially refreshed current fact use 2026-08-14, the audit date in Asia/Dubai.

## Scope

The review covered:

- 120 MCP tools across 37 features;
- 16 curated JSON packs, the setup advisor, and two agent domains;
- shared HTTP, OAuth, error, health, schema, and discovery code;
- packaging, source and wheel contents, Python compatibility, tests, linting, typing, and coverage;
- GitHub Actions, dependency update policy, publication paths, and secret handling;
- current anonymous upstream behavior and selected high-risk UAE business rules;
- README, credential, contribution, disclaimer, release, and registry claims.

## Material findings resolved

### Tax and business guidance

- Corrected the QFZP estimator. A QFZP no longer receives the ordinary AED 375,000 0% band or a Small Business Relief suggestion. The full taxable income is split between qualifying income at 0% and other taxable income at 9%, subject to the tool's eligibility warnings. This follows the [FTA Free Zone Persons guide](https://tax.gov.ae/Datafolder/Files/Guides/CT/Free%20Zone%20Persons%20-%2020%2005%202024%20final%20for%20GCD.pdf).
- Changed `free_only=True` to require an explicitly verified `is_free: true`. Paid, subsidized, equity-linked, and unknown-cost programs can no longer be presented as free.
- Replaced unsupported bank co-shareholder advice and hard DUL bank-eligibility claims with a dated, sourced integration snapshot and clear average-versus-guarantee wording.
- Corrected the Resolution 11 of 2025 regularisation deadline and conditional mainland route against the [official Dubai legislation](https://dlp.dubai.gov.ae/Legislation%20Reference/2025/Executive%20Council%20Resolution%20No.%20%2811%29%20of%202025%20Regulating%20the%20Conduct%20of%20Free%20Zone%20Establishments%E2%80%99%20Activities.html).
- Corrected Dubai Chamber membership scope and fee categories, free-zone sources, trademark fees, GCC patent wording, Create Apps dates, and private-market pricing caveats.
- Completed a full record-by-record funding review. Current Hub71 and Dubai SME deadlines, in5 terms, VC mandates, DFDF snapshots, Khalifa Fund loan taxonomy, exclusions, and sources were reconciled; unsupported tickets and claims were removed.
- Rechecked the e-invoicing register. On 2026-08-14, the [official MoF ASP page](https://mof.gov.ae/en/about-us/initiatives/einvoicing/einvoicing-accredited-service-providers-asps/) listed 42 pre-approved, 38 accredited, and 9 in final assessment. The lists overlap and are not added together.

### Security and publication

- Prevented WAQI query-token disclosure in embedded or mounted use. HTTP dependency logs now default to a safe level and retain credential redaction even if a host re-enables INFO logging.
- Made malformed dependency log records fail closed: formatting failures now replace the message and clear raw arguments before anything reaches stderr.
- Redacted sensitive query parameters, headers, bearer values, and echoed credentials from HTTP error excerpts.
- Made OAuth token caching credential-bound, monotonic-clock based, single-flight within an event loop, failure-coalesced, and safe across sequential event loops.
- Rejected DTD-bearing Makani XML and used a hardened parser.
- Restricted manual production publication to `main`, pinned third-party Actions to immutable commits, pinned and checksum-verified the MCP publisher binary, reduced workflow permissions, and added concurrency controls.
- Added weekly Dependabot checks for Python and GitHub Actions.

### API correctness and resilience

- Added structured failures for malformed successful responses from AlAdhan, aviation weather, currency, Open-Meteo, OSM Overpass, Dubai Pulse, DLD, RTA, Quran Cloud, and catalog paths where applicable.
- Enforced caller limits for DLD and RTA responses instead of trusting an over-delivering upstream.
- Hardened data.dubai pagination and shape validation, DFM parsing, Quran result bounds, Makani parsing, and RTA GTFS handling.
- Fixed health-state semantics so lifetime and consecutive failures are distinct, successful observations reset consecutive failures, configured-but-unobserved sources remain unknown, and all used sources are registered.
- Corrected holiday confirmation versus provisional status and removed false certainty around the Prophet's Birthday observance.

### Knowledge freshness

- Added `full_review_date` to the shared schema, all JSON packs, tool responses, status registry, docs, and contribution rules.
- The scheduled checker now covers all 19 domains, including code-only `setup_advisor`, `data_analyst`, and `arabic_writer`.
- Full-review budgets are 100 days for high-volatility domains, 190 days for medium, and 365 days for stable domains. Targeted updates cannot reset those clocks.

## Release state

- Local source and `server.json` identify version 0.4.0.
- The public [PyPI project](https://pypi.org/project/mcp-dubai/) still serves 0.2.0.
- No public MCP Registry record was found during the 2026-08-14 check.
- Publication was intentionally not performed. A maintainer must decide whether 0.4.0 is ready, create the release, and confirm Trusted Publishing plus registry ownership.

## Remaining bounded risks and decisions

1. Enable required reviewers and a deployment branch policy on the GitHub `pypi` environment. The workflow now blocks manual production publication from non-main refs, but repository environment protection is an administrator setting and was not changed by this audit.
2. Obtain representative data.dubai OAuth credentials for an opt-in live contract test. Credential-free behavior and mocked OAuth paths are covered, but entitlement-dependent datasets cannot be fully proven anonymously.
3. Keep monitoring the CBUAE base-rate and FCSC services. Current failures are upstream access blocks, not local authentication failures.
4. Rebuild the full KHDA school snapshot from an authoritative current workbook when available. The August update corrected audited records without pretending the complete bundled snapshot was rebuilt.
5. Consider a bounded response cache and circuit breaker for repeated live calls. Current retries are safe, but high-volume deployments can still amplify slow upstreams.
6. Consider an upstream query strategy for Quran search that does not download a large complete response before local filtering.
7. Keep tool discovery as the primary catalogue surface. A complete MCP `tools/list` response is large enough that clients should avoid placing the entire catalogue into every prompt.

## Overall assessment

The repository is fit for continued alpha use and maintainer release review. The audit found and corrected issues that could have caused a materially wrong tax estimate, unsafe funding filtering, credential disclosure, stale-content masking, cross-loop OAuth failure, oversized upstream responses, and publication from an unintended branch. Remaining items are explicit operational or upstream constraints rather than hidden correctness claims.
