# MCP-Dubai audit - 2026-10-20

## Result and scope

Routine audit as of **20 October 2026, Asia/Dubai**, covering changes since the 13 October audit. The strict freshness gate passed on entry, but `tax_compliance` would have reached its 100-day full-review budget on 2 November, so it received a **full review**. Every other knowledge domain received a targeted check for news since 13 October, every pack URL was link-checked, dependencies were checked for releases and advisories, open Dependabot updates were applied, and anonymous upstream integrations were called live.

The catalogue remains **120 tools, 37 features and 19 knowledge domains**; version stays **0.4.0**. `tax_compliance` carries `knowledge_date` and `full_review_date` 2026-10-20. Packs with targeted changes advance only `knowledge_date`.

## Dependencies and CI

- **FastMCP:** floor moves to **3.4.9** (`fastmcp>=3.4.9,<4`). 3.4.9 (16 Oct 2026) backports security fixes from 4.1: OpenAPI dot-segment rejection, skill containment, and bounded regex tool search.
- **mcp:** new direct floor `mcp>=1.30.0,<2`. pip-audit flagged **CVE-2026-59951** (GHSA-84m7-p3x7-pcfv) in mcp 1.29.0, which affects unbounded session accumulation in stateful Streamable HTTP. This server ships stdio, which is not affected, but `fastmcp run --transport http` would be. After the upgrade, pip-audit reports **no known vulnerabilities**.
- **Dependabot:** applied directly on `main`: hatchling 1.32.4, codecov-action 7.1.1, upload-artifact 7.0.2, download-artifact 8.0.2. Each pinned SHA was checked against its release tag.
- **Not applied:** the Dependabot range bump to `fastmcp<5`. It fails strict mypy because FastMCP 4 renames the `ToolAnnotations` hint arguments to snake_case (`readOnlyHint` becomes `read_only_hint`) and pulls mcp 2.x. The v4 migration remains out of scope.
